# Portfolio on minikube

Manifests for running the Go app and PostgreSQL on a local minikube cluster, exposed through the
minikube ingress addon at <http://portfolio.local>.

Scope of this deployment: **application + PostgreSQL only**. There is no Prometheus, Loki, Tempo,
Grafana or OTel Collector here, so traces are not exported (the app tolerates this and starts fine).

## What gets created

| Resource | Name | Notes |
| --- | --- | --- |
| Namespace | `portfolio` | |
| Secret | `portfolio-db` | DB users/passwords + `DATABASE_URL`, generated by the deploy script |
| ConfigMap | `postgres-initdb` | Creates the least-privilege `portfolio_app` role on first DB init |
| StatefulSet | `postgres` | `postgres:18`, 2 Gi PVC, headless Service on 5432 |
| ConfigMap | `portfolio-app-config` | Non-secret application environment |
| PVC | `portfolio-uploads` | 1 Gi for uploaded thumbnails |
| Deployment | `portfolio` | 1 replica, `migrate` init container then `serve` |
| Service | `portfolio` | ClusterIP `80 -> 8080` |
| Ingress | `portfolio` | host `portfolio.local`, class `nginx` |
| Job | `create-admin` | One-shot, only applied by `scripts/k8s-create-admin.sh` |

## 0. Prerequisites

```bash
minikube status
kubectl config current-context        # must be "minikube"
docker manifest inspect nam2107/portfolio:dc3aef79b8ac >/dev/null && echo "image exists"
```

Make the helper scripts executable:

```bash
chmod +x scripts/k8s-*.sh
```

## 1. Deploy

```bash
./scripts/k8s-deploy.sh
```

The script enables the ingress addon, waits for the controller, creates the `portfolio-db` secret
(random passwords) if it does not exist, applies `deploy/k8s`, and waits for both workloads.

Equivalent manual commands, if you prefer:

```bash
minikube addons enable ingress
kubectl -n ingress-nginx rollout status deployment/ingress-nginx-controller --timeout=300s

kubectl apply -f deploy/k8s/namespace.yaml

POSTGRES_PASSWORD="$(openssl rand -hex 24)"
APP_DB_PASSWORD="$(openssl rand -hex 24)"
DATABASE_URL="postgres://portfolio_app:${APP_DB_PASSWORD}@postgres:5432/portfolio?sslmode=disable"
kubectl -n portfolio create secret generic portfolio-db \
  --from-literal=POSTGRES_DB=portfolio \
  --from-literal=POSTGRES_USER=portfolio_admin \
  --from-literal=POSTGRES_PASSWORD="$POSTGRES_PASSWORD" \
  --from-literal=APP_DB_USER=portfolio_app \
  --from-literal=APP_DB_PASSWORD="$APP_DB_PASSWORD" \
  --from-literal=DATABASE_URL="$DATABASE_URL"

kubectl apply -k deploy/k8s
kubectl -n portfolio rollout status statefulset/postgres --timeout=300s
kubectl -n portfolio rollout status deployment/portfolio --timeout=300s
```

## 2. Add the hosts entry (once per machine)

```bash
echo "$(minikube ip) portfolio.local" | sudo tee -a /etc/hosts
```

Then open <http://portfolio.local>. To remove the entry later:

```bash
sudo sed -i '/portfolio\.local/d' /etc/hosts
```

## 3. Verify

```bash
kubectl -n portfolio get pods,pvc,svc,ingress
kubectl -n portfolio logs statefulset/postgres --tail=50
kubectl -n portfolio logs deployment/portfolio --tail=50
kubectl -n portfolio logs deployment/portfolio -c migrate --tail=50   # migration output

curl -i http://portfolio.local/healthz     # 200 "ok"
curl -i http://portfolio.local/readyz      # 200 "ready" (checks DB)
curl -i http://portfolio.local/projects    # 200
curl -i -H 'Host: portfolio.local' "http://$(minikube ip)/healthz"   # bypasses /etc/hosts

kubectl port-forward -n portfolio svc/portfolio 8080:80 --address 0.0.0.0
```

`./scripts/smoke.sh` is **not** suitable here: it asserts it sees the `app1`, `app2`, `app3`
instances from the Compose setup. Use the individual checks above instead.

## 4. Create the first admin

```bash
./scripts/k8s-create-admin.sh
```

It prompts for username/password, puts them in a temporary `portfolio-admin` secret, runs the
`create-admin` Job, prints its logs, then deletes the secret and the Job.

Then sign in at <http://portfolio.local/admin/login> and, optionally, run the CRUD check:

```bash
BASE_URL=http://portfolio.local ./scripts/curl-crud.sh
```

## 5. Day-2 operations

Deploy a new image tag (the `migrate` init container must be updated too):

```bash
NEW_TAG=dc3aef79b8ac
kubectl -n portfolio set image deployment/portfolio \
  migrate=nam2107/portfolio:"$NEW_TAG" \
  portfolio=nam2107/portfolio:"$NEW_TAG"
kubectl -n portfolio rollout status deployment/portfolio --timeout=300s
```

Or edit the tag in `deploy/k8s/app/deployment.yaml` (and `deploy/k8s/jobs/create-admin-job.yaml`)
and run `kubectl apply -k deploy/k8s`.

Change non-secret settings (allowed hosts, public URL, cookie flags):

```bash
$EDITOR deploy/k8s/app/configmap.yaml
kubectl apply -k deploy/k8s
kubectl -n portfolio rollout restart deployment/portfolio
```

Change DB credentials (destructive if the DB already exists — the role is only created on first
init):

```bash
kubectl -n portfolio delete secret portfolio-db
./scripts/k8s-deploy.sh
```

Scale the app (uploads PVC is `ReadWriteOnce`; all replicas land on the single minikube node, so
this works, but start with 1):

```bash
kubectl -n portfolio scale deployment/portfolio --replicas=3
```

## 6. Troubleshooting

**Pod stuck in `ImagePullBackOff` / `ErrImagePull`**

```bash
kubectl -n portfolio describe pod -l app.kubernetes.io/name=portfolio
minikube ssh -- sudo crictl pull nam2107/portfolio:dc3aef79b8ac
```

**App restarts, `DATABASE_URL is required` or `postgres remained unavailable`**

```bash
kubectl -n portfolio get secret portfolio-db -o jsonpath='{.data.DATABASE_URL}' | base64 -d; echo
kubectl -n portfolio logs statefulset/postgres --tail=100
kubectl -n portfolio exec statefulset/postgres -- psql -U portfolio_admin -d portfolio -c '\du'
```

The `portfolio_app` role is created only when PostgreSQL initializes an empty data directory. If you
changed the secret after the first start, either reset the DB (below) or create/alter the role
manually.

**Ingress returns 404**

```bash
kubectl -n ingress-nginx get pods
kubectl -n portfolio describe ingress portfolio
getent hosts portfolio.local
```

Remember the Ingress matches on `Host: portfolio.local`; requesting the minikube IP without that
host header hits the default backend.

**Uploads fail with permission denied**

```bash
kubectl -n portfolio logs deployment/portfolio -c fix-perms
kubectl -n portfolio exec deployment/portfolio -- /app/portfolio healthcheck
```

The `fix-perms` init container chowns `/app/uploads` to `65532:65532`.

**Login returns 429**

The app rate-limits `/admin/login` to 5 requests/minute per IP. Wait a minute or restart the pod:

```bash
kubectl -n portfolio rollout restart deployment/portfolio
```

**Tracing/OTLP errors in logs**

Expected: no collector is deployed. Either ignore them or deploy an OTel Collector and point
`OTEL_EXPORTER_OTLP_ENDPOINT` at its Service.

## 7. Reset the database (destroys data)

```bash
kubectl -n portfolio scale statefulset/postgres --replicas=0
kubectl -n portfolio delete pvc data-postgres-0
kubectl -n portfolio scale statefulset/postgres --replicas=1
kubectl -n portfolio rollout status statefulset/postgres --timeout=300s
```

If you also rotated `portfolio-db`, delete and recreate it first, then scale back up.

## 8. Teardown

```bash
./scripts/k8s-teardown.sh                # deletes the namespace (DB + uploads included)
./scripts/k8s-teardown.sh --disable-ingress
sudo sed -i '/portfolio\.local/d' /etc/hosts
```
