# Argo CD (GitOps CD)

Argo CD continuously reconciles two Applications from the **`deploy` branch** of
`https://github.com/zetasuna/portfolio.git`:

| Application | Path | Namespace |
| --- | --- | --- |
| `portfolio-app` | `deploy/k8s` | `portfolio` |
| `portfolio-observability` | `deploy/k8s/observability` | `observability` |

Jenkins never talks to Kubernetes. It builds/pushes the image and then copies
the manifests from `main` into the `deploy` branch with a new image tag. Argo CD
polls that branch every 60 seconds and rolls the change out.

## Branch model

- `main` is the developer branch. CI runs here.
- `deploy` is generated by `scripts/ci-gitops-bump.sh`: it mirrors `deploy/`
  from the build commit and differs only by the image tag in
  `deploy/k8s/kustomization.yaml`.
- Do not edit `deploy` by hand. Argo CD watches it; the next pipeline run
  overwrites it from `main`.

The repository is public, so Argo CD needs no repository credentials. If it
becomes private, add a deploy key/HTTPS credential under
**Settings → Repositories** in Argo CD.

## Bootstrap (one time)

```bash
./scripts/argocd-bootstrap.sh
```

The script:

1. Creates the `deploy` branch from `HEAD` if it does not exist.
2. Installs the pinned Argo CD release (`install.yaml`, v3.6.1).
3. Registers both Applications.

Add the host entry once:

```bash
echo "$(minikube ip) argocd.local" | sudo tee -a /etc/hosts
```

Open <http://argocd.local> and sign in as `admin` with:

```bash
kubectl -n argocd get secret argocd-initial-admin-secret \
  -o jsonpath='{.data.password}' | base64 -d; echo
```

Change that password immediately. Store it in Jenkins as the
`argocd-admin-password` credential (the pipeline only uses it to wait for sync).

## First sync / adopting existing workloads

The namespaces were created with `kubectl apply -k` before Argo CD existed.
Argo CD adds its tracking metadata on the first sync; it does not recreate
Deployments, StatefulSets, PVCs or ConfigMaps.

Review after bootstrap (auto-sync may already have applied the identical
manifests):

```bash
argocd login argocd.local --plaintext --grpc-web
argocd app get portfolio-app
argocd app get portfolio-observability
argocd app diff portfolio-app
argocd app diff portfolio-observability
```

Then confirm the workloads and volumes were adopted, not recreated:

```bash
argocd app list
kubectl -n portfolio get deploy,sts,pvc
kubectl -n observability get deploy,ds,pvc
```

`portfolio-db` and `grafana-admin` are created by the bootstrap scripts and are
**not** in Git, so Argo CD leaves them alone. Never move those secrets into Git
without a proper secret manager.

> The `observability` Application currently reports `Degraded` while the Alloy
> DaemonSet is not ready. That is a pre-existing workload issue, not a sync
> problem; fix it before treating Argo health as a deploy gate.

## Day-2 operations

All changes go through Git:

```bash
# edit manifests on main
git commit && git push origin main
# the next pipeline run copies main -> deploy and pins the image tag

# roll back only the image (GitOps way)
git revert <gitops-commit-on-deploy-branch>

# roll back through Argo history
argocd app history portfolio-app
argocd app rollback portfolio-app <history-id>
```

`kubectl apply -k` / `kubectl set image` are now bootstrap/emergency tools only.
If you use them, Argo CD will revert the drift on its next sync (`selfHeal`).

## Upgrade

Replace `deploy/argocd/install.yaml` with the manifest from the new release,
update the version in this file, then:

```bash
kubectl apply --server-side -k deploy/argocd
kubectl -n argocd rollout status deployment/argocd-server --timeout=300s
```

## Access model

The UI is exposed over plain HTTP at `argocd.local` behind the minikube ingress
(`server.insecure=true`). Keep it on the local machine or behind a VPN/TLS proxy;
do not expose it publicly.

For a least-privilege CI token, add a local account with `apiKey` capability and
a read-only RBAC role, then store the token as `argocd-token`. The pipeline in
this repository uses the admin password for simplicity; swap it for a token
before using this outside a homelab.
